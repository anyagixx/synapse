# Synapse — Как построить приложение с помощью AI

> **Ты никогда не писал код? Это для тебя.**
> Ты просто говоришь AI что хочешь. Synapse enforced правила и инструменты.

---

## Что такое Synapse?

Synapse — невидимый помошник который:
- Даёт AI **12 инструментов** для поиска, проверки, генерации контрактов и навигации по коду
- Заставляет AI следовать GRACE методологии (Phase 0, контракты, верификация)
- Экономит токены на каждой shell-команде
- **Сам проходит собственные проверки** — доказательство что методология работает

**AI сама решает когда использовать инструменты. Ты их не вызываешь.**

---

## Твой первый проект (2 минуты)

```bash
mkdir my-notes-app && cd my-notes-app
syn init          # одна команда — всё настроено
opencode          # запуск AI
```

Внутри OpenCode AI скажет:
> «Что ты хочешь построить?»

Ты отвечаешь:
> «Приложение для заметок с поиском по тексту»

AI дальше делает всё сама:
1. Заполняет `docs/requirements.xml` — что строим
2. Заполняет `docs/technology.xml` — на чём
3. Заполняет `docs/development-plan.xml` — модули и фазы
4. Заполняет `docs/verification-plan.xml` — как проверять
5. Заполняет `docs/knowledge-graph.xml` — связи модулей
6. **Только потом** пишет код с MODULE_CONTRACT и START_/END_ блоками
7. После каждого модуля: `verify_project` → fix → re-verify
8. В конце: `review_code` + `refresh_project`

## Что делает `syn init`

Создаёт интеграцию с OpenCode:

| Что | Зачем |
|-----|-------|
| `AGENTS.md` | GRACE-конституция — AI читает каждую сессию |
| `opencode.jsonc` | Авто-старт MCP — 12 инструментов |
| `docs/*.xml` (5 файлов) | Phase 0 шаблоны архитектуры |
| `.opencode/plugins/synapse.ts` | Авто-прокси + GRACE-правила |
| `.opencode/rules/synapse.md` | Инструкции для AI |
| `.opencode/package.json` | Зависимости плагина |

---

## Phase 0: сначала архитектура, потом код

AI **не может писать код** пока не созданы все 5 файлов в `docs/`.

3 слоя enforcement:
1. **AGENTS.md**: «You MAY NOT write source code in Phase 0»
2. **Плагин**: «If ANY docs file missing → STOP»
3. **Шаблоны**: AI видит что именно заполнить

## 12 MCP инструментов

| Инструмент | Когда AI вызывает |
|-----------|-----------------|
| `semantic_search` | Найти существующий код (BM25 + вектор) |
| `view_signatures` | Посмотреть структуру файла |
| `graphrag_query` | Понять связи между модулями |
| `verify_project` | После каждого изменения (11 проверок) |
| `review_code` | Перед «готово» (3 режима) |
| `project_status` | Общая картина здоровья |
| `token_savings` | Экономия токенов |
| `compress_text` | Сжать большой текст |
| `refresh_project` | Синхронизировать граф с кодом |
| `suggest_contract` | Сгенерировать MODULE_CONTRACT |
| `lsp_hover` | Посмотреть тип/сигнатуру |
| `lsp_references` | Найти использования символа |

## Команды (редко нужны)

```bash
syn doctor         # 10 проверок — всё настроено?
syn index --watch  # Авто-переиндексация
syn status         # Здоровье проекта
syn verify         # Проверка контрактов и структуры
syn refresh        # Синхронизация artifacts
syn gain           # Токены сэкономлены
syn serve          # Web дашборд (http://127.0.0.1:3100)
```

---

## Если что-то не работает

```bash
syn doctor    # Покажет какая из 10 проверок FAIL
```

## Советы

1. `syn init` — один раз в начале
2. `syn index --watch` — в соседнем терминале
3. `syn serve` — web дашборд для визуального контроля
4. `syn gain` — экономия в конце сессии
5. Не думай о Synapse — он работает сам
