# Synapse — Как построить приложение с помощью AI

> **Ты никогда не писал код? Это для тебя.**
> Ты просто говоришь AI что хочешь. Synapse enforced правила чтобы AI делал всё правильно.

---

## Что такое Synapse?

Synapse — это невидимый помошник который:
- Даёт AI 8 инструментов для поиска и проверки кода
- Заставляет AI следовать правильной методологии (GRACE)
- Экономит токены на каждой команде

**AI сама решает когда использовать инструменты. Ты их не вызываешь.**

---

## Твой первый проект (2 минуты)

```bash
mkdir my-notes-app && cd my-notes-app
syn init          # одна команда — всё настроено
opencode          # запуск AI
```

Внутри OpenCode AI скажет примерно:
> «Я вижу шаблоны архитектуры в docs/. Что ты хочешь построить?»

Ты отвечаешь:
> «Приложение для заметок с поиском по тексту»

AI дальше делает всё сама:
1. Заполняет `docs/requirements.xml` — что строим
2. Заполняет `docs/technology.xml` — на чём
3. Заполняет `docs/development-plan.xml` — модули и фазы
4. Заполняет `docs/verification-plan.xml` — как проверять
5. Заполняет `docs/knowledge-graph.xml` — связи модулей
6. **Только потом** пишет код с MODULE_CONTRACT и START_/END_ блоками
7. После каждого модуля вызывает `verify_project`
8. В конце вызывает `review_code`

## Что делает `syn init`

Создаёт 5 файлов + 5 XML-шаблонов:

| Что | Зачем |
|-----|-------|
| `AGENTS.md` | GRACE-конституция — AI читает каждую сессию |
| `opencode.jsonc` | Авто-старт MCP — AI получает 8 инструментов |
| `docs/requirements.xml` | Шаблон: что строим |
| `docs/technology.xml` | Шаблон: на чём строим |
| `docs/development-plan.xml` | Шаблон: модули и фазы |
| `docs/verification-plan.xml` | Шаблон: как проверять |
| `docs/knowledge-graph.xml` | Шаблон: связи модулей |
| `.opencode/plugins/synapse.ts` | Авто-прокси + GRACE-правила |
| `.opencode/rules/synapse.md` | Инструкции для AI |
| `.opencode/package.json` | Зависимости плагина |

---

## Phase 0: сначала архитектура, потом код

AI **не может писать код** пока не созданы все 5 файлов в `docs/`.

Это enforced через 3 слоя:
1. **AGENTS.md**: «You are in Phase 0 until ALL 5 files exist. You MAY NOT write source code.»
2. **Плагин**: «If ANY of 5 files is missing → STOP. DO NOT create source files.»
3. **Шаблоны**: AI видит что именно нужно заполнить

Ты просто говоришь что хочешь. AI сама заполнит docs → потом напишет код.

## 8 MCP инструментов

| Инструмент | AI вызывает когда |
|-----------|-----------------|
| `semantic_search` | Найти существующий код |
| `view_signatures` | Посмотреть структуру файла |
| `graphrag_query` | Понять связи между модулями |
| `verify_project` | После каждого изменения |
| `review_code` | Перед тем как сказать «готово» |
| `project_status` | Показать общую картину |
| `token_savings` | Показать экономию |
| `compress_text` | Сжать большой текст |

## CLI команды (редко нужны)

```bash
syn doctor         # Проверить что всё настроено (10 проверок)
syn index          # Переиндексировать код
syn index --watch  # Авто-переиндексация при изменениях
syn status         # Здоровье проекта
syn gain           # Сколько токенов сэкономлено
```

---

## Если что-то не работает

```bash
syn doctor    # Покажет все 10 проверок — какая FAIL
```

## Советы

1. `syn init` — один раз в начале проекта
2. `syn index --watch` — в соседнем терминале для авто-переиндексации
3. `syn gain` — в конце сессии посмотреть экономию
4. Не думай о Synapse — он работает сам
